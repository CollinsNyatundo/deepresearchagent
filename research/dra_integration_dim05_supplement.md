## Key Findings

### 1. DOCX Export Requires Image Embedding Strategy

**Claim:** Research reports often contain images (charts, diagrams, screenshots from scraped sources). Embedding images in DOCX requires either base64 encoding (increases file size) or separate image files referenced via relationships.[^1]

**Source:** python-docx Image Handling Documentation

**URL:** https://python-docx.readthedocs.io/en/latest/api/document.html

**Date:** 2026

**Excerpt:**
> "The add_picture() method adds a picture at the end of the document. The picture is added as a paragraph with a single run containing the picture."

**Context:** The DRA plan proposes `export_docx()` but does not specify how images are handled. Research reports may contain:
- Mindmap images (generated by G6)
- Knowledge graph visualizations (generated by D3)
- Screenshots from scraped web pages
- Chart images from experiments

python-docx's `add_picture()` accepts a file path or file-like object. For DRA, images are stored in memory or in the database, so the export function must:
1. Extract images from the report Markdown (find `![alt](url)` markers)
2. Download or load the image data
3. Embed it in the DOCX using `add_picture()`

For images referenced by URL (e.g., scraped web pages), the export function must download the image first, which adds network latency and failure risk.

**Recommendation:** Store images as base64 in the report during synthesis, then decode and embed during export. This avoids network calls during export but increases report size.

**Confidence:** High

The existing `wiki_links.py` parser can be extended to generate the vault structure.

### 3. BibTeX Edge Cases: Unicode and Special Characters

**Claim:** BibTeX has strict encoding requirements. Unicode characters (accents, non-ASCII characters in author names) require LaTeX escapes or UTF-8 encoding with BibTeX 8.0+. The DRA plan does not address character encoding.[^3]

**Source:** BibTeX Formatting Guide (Tame the BeaST)

**URL:** http://tug.ctan.org/info/bibtex/tamethebeast/ttb_en.pdf

**Date:** 2026

**Excerpt:**
> "BibTeX only supports 7-bit ASCII characters. For accented characters, use LaTeX escapes (e.g., 'e for é)."

**Context:** Academic papers often have non-ASCII characters in author names, titles, and journal names. For example:
- "José García" → `Jos{\'e} Garc{\'i}a`
- "naïve" → `na{\"i}ve`
- "Müller" → `M{\"u}ller`

The DRA plan's BibTeX generation must either:
1. Use a library like `latexcodec` or `pybtex` for automatic escaping
2. Require UTF-8 BibTeX (BibTeX 8.0 or biber) and set encoding in the BibTeX file header
3. Use Unicode-aware BibTeX tools like `biblatex` with `biber` backend

**Recommendation:** Use `pybtex` library for BibTeX generation. It handles Unicode, LaTeX escaping, and multiple BibTeX styles automatically.

```python
from pybtex.database import BibliographyData, Entry
from pybtex.backends.bibtex import Writer

def generate_bibtex(citations: list[Citation]) -> str:
    bib_data = BibliographyData()
    for citation in citations:
        entry = Entry('article', fields={
            'title': citation.title,
            'author': ' and '.join(citation.authors),
            'year': str(citation.year),
            'doi': citation.doi,
            'url': citation.url,
        })
        bib_data.add_entry(citation.id, entry)
    
    return bib_data.to_string('bibtex')
```

**Confidence:** High

### 4. RIS Format Has Specific Tag Requirements

**Claim:** RIS format uses two-letter tags (TY, TI, AU, PY, etc.) with specific formatting rules. The DRA plan mentions RIS export but does not detail the tag mapping.[^4]

**Source:** RIS Format Specification

**URL:** https://en.wikipedia.org/wiki/RIS_(file_format)

**Date:** 2026

**Excerpt:**
> "TY - JOUR\nTI - Article Title\nAU - Author, A.\nPY - 2026\nER -"

**Context:** RIS format requires specific tags for different document types:
- `TY` - Type (JOUR for journal, BOOK for book, WEB for web page)
- `TI` - Title
- `AU` - Author (one per line, last name first)
- `PY` - Publication year
- `DO` - DOI
- `UR` - URL
- `AB` - Abstract
- `KW` - Keywords
- `ER` - End of reference (required)

The mapping from DRA's `Citation` model to RIS tags:

```python
RIS_TAG_MAP = {
    'title': 'TI',
    'authors': 'AU',
    'year': 'PY',
    'doi': 'DO',
    'url': 'UR',
    'abstract': 'AB',
    'journal': 'JO',
    'volume': 'VL',
    'issue': 'IS',
    'pages': 'SP',
}

def citation_to_ris(citation: Citation) -> str:
    lines = [f"TY  - JOUR"]  # Default to journal; detect web sources
    lines.append(f"TI  - {citation.title}")
    for author in citation.authors:
        lines.append(f"AU  - {author}")
    lines.append(f"PY  - {citation.year}")
    if citation.doi:
        lines.append(f"DO  - {citation.doi}")
    if citation.url:
        lines.append(f"UR  - {citation.url}")
    lines.append("ER  -")
    return "\n".join(lines)
```

**Confidence:** High

### 5. Pandoc is the Best Path for Multi-Format Export

**Claim:** Pandoc can convert Markdown to DOCX, LaTeX, PDF, and HTML in a single pipeline. For DRA, using Pandoc as the primary export engine reduces code duplication and ensures consistent formatting across formats.[^5]

**Source:** Pandoc Documentation

**URL:** https://pandoc.org/

**Date:** 2026

**Excerpt:**
> "Pandoc is a Haskell library for converting from one markup format to another, and a command-line tool that uses this library."

**Context:** Instead of implementing separate export functions for each format, DRA can:
1. Generate enhanced Markdown with YAML frontmatter and citations
2. Pass it through Pandoc with appropriate options
3. Get DOCX, LaTeX, PDF, or HTML output

```python
async def export_report(report: str, citations: list, format: str) -> bytes:
    # Generate enhanced Markdown
    md = generate_enhanced_markdown(report, citations)
    
    # Use Pandoc for conversion
    if shutil.which("pandoc"):
        return await pandoc_convert(md, format)
    
    # Fallback to format-specific libraries
    if format == "docx":
        return python_docx_convert(md)
    elif format == "bibtex":
        return generate_bibtex(citations)
    elif format == "ris":
        return generate_ris(citations)
    elif format == "obsidian":
        return generate_obsidian_vault(report, citations)
```

**Pandoc advantages:**
- Handles images, tables, and math automatically
- Supports citation processing (CiteProc) with CSL styles
- Generates professional-quality documents
- Active development, well-documented

**Pandoc disadvantages:**
- Requires installation (~50MB binary)
- Haskell dependency (not available on all platforms)
- Not installable via pip (requires system package manager)

**Recommendation:** Make Pandoc the primary export engine with python-docx/fallback for environments without Pandoc.

**Confidence:** High

## Tensions and Counter-Arguments

### Tension 1: Pandoc Dependency vs. Pure Python

Pandoc provides the best quality but is a system dependency. python-docx is pure Python but limited in features.

**Counter-argument:** Use a hybrid approach: Pandoc when available, python-docx fallback. Document the Pandoc requirement for high-quality export. For CI/CD and serverless environments, pre-install Pandoc in the Docker image.

### Tension 2: Obsidian Vault Complexity vs. User Value

A full Obsidian vault export with proper linking, metadata, and structure is complex. Users may just want a single Markdown file.

**Counter-argument:** Offer two Obsidian export options:
1. **Simple:** Single Markdown file with YAML frontmatter
2. **Full Vault:** Complete vault structure with linked notes, attachments, and metadata

Default to simple; full vault as an advanced option.

### Tension 3: BibTeX/RIS Redundancy

BibTeX and RIS serve the same purpose (bibliography export). Supporting both is redundant.

**Counter-argument:** BibTeX is for LaTeX users; RIS is for reference managers (Zotero, Mendeley). Both are standard in academia. Support BibTeX first (more common), add RIS if users request it.

### 2. Use Pandoc as Primary Export Engine

```python
import subprocess
import tempfile
import os

async def pandoc_convert(md_content: str, output_format: str) -> bytes:
    with tempfile.NamedTemporaryFile(mode='w', suffix='.md', delete=False) as f:
        f.write(md_content)
        input_path = f.name
    
    output_path = input_path.replace('.md', f'.{output_format}')
    
    try:
        subprocess.run([
            'pandoc', input_path,
            '-o', output_path,
            '-f', 'markdown',
            '-t', output_format,
            '--citeproc',  # Enable citation processing
        ], check=True, capture_output=True)
        
        with open(output_path, 'rb') as f:
            return f.read()
    finally:
        os.unlink(input_path)
        if os.path.exists(output_path):
            os.unlink(output_path)
```

```python
from pybtex.backends.bibtex import Writer

def generate_bibtex(citations: list) -> str:
    bib_data = BibliographyData()
    for citation in citations:
        entry = Entry('article', fields={
            'title': citation.title,
            'year': str(citation.year),
            'doi': citation.doi,
            'url': citation.url,
        })
        for author in citation.authors:
            entry.persons['author'] = [Person(author)]
        bib_data.add_entry(citation.id, entry)
    
    return bib_data.to_string('bibtex')
```
